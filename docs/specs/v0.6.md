# Spec: modelduel v0.6.0 «Informe en Markdown»

Estado: propuesta del agente `builder` (agent-project-2), a partir del encargo de Alberto. El
encargo ya traía objetivo, alcance y criterios, así que no hubo entrevista; las suposiciones
están en su sección.

## Objetivo

1. **Exportar a Markdown.** Quien comparte un duelo en un PR o un issue de GitHub quiere pegar un
   texto, no adjuntar un HTML. `modelduel report results.json --format md --out DIR` (y
   `modelduel run … --format html,md`) genera `informe.md`: marcador, veredicto con su criterio,
   tabla por tarea y por contendiente, coste y avisos («una sola ejecución es una señal débil»).
2. **Seguridad del Markdown.** Todo texto que viene de `results.json` (modelos, títulos, estados,
   moneda, versión, fechas) es dato **no fiable**: un `results.json` ajeno no debe poder inyectar
   enlaces, imágenes, HTML, menciones (`@usuario`), referencias (`#12`), filas de tabla ni
   encabezados en el informe que alguien pegue en GitHub.
3. **Capturas del duelo en directo.** Regenerar `modelduel-despues-directo.png` y
   `modelduel-despues-resultado.png` (la web actual dice «▲ primero» y trae la salvedad del
   informe) para el informe de sesión del curso.

Éxito: pegar `informe.md` en un comentario de GitHub se ve bien (tablas, negritas) y un
`results.json` hostil no produce ni un enlace, ni HTML, ni una fila de más.

## Alcance

**`markdown`** (`src/modelduel/report/markdown.py`, `tests/test_markdown.py`)
- `render_markdown(results) -> str`; sirve para duelo de dos y para liga (2 a 6), con los mismos
  `summary` y `rank_sides`/`decide` que el informe HTML y la clasificación.
- Contenido: título, aviso de duelo incompleto (si `status == "in_progress"`), marcador por
  contendiente (tareas, tests, tiempo, tokens, coste), veredicto con su criterio
  (tareas → tests → coste, igual que `decide`), tabla por tarea con los tests de cada
  contendiente y su estado si no es `ok`, nota de precios ficticios o de monedas no comparables,
  aviso de pocas ejecuciones y pie con versión y enlace a la web.
- No incluye código ni salida de pytest de los modelos: el informe es para pegar en un hilo, el
  detalle está en el HTML.
- **Escapado** (`md_text`), para todo dato procedente de `results.json`:
  - Normaliza a una línea (saltos de línea y espacios repetidos → un espacio); quita caracteres de
    control y de dirección Unicode (U+202A-202E, U+2066-2069); recorta con «…».
  - Escapa con barra invertida: `\`, `` ` ``, `*`, `_`, `~`, `[`, `]`, `(`, `)`, `<`, `>`, `|`,
    `&`, `!`, `#`, `@`, y `:` o `.` cuando formarían un autoenlace (`http://`, `www.`);
    escapa también un `-`, `+`, `=` o `1.` al empezar. Así no hay enlaces, imágenes, HTML en línea,
    entidades, menciones, referencias ni filas de tabla.
  - Los números se fuerzan con `int()`/formato propio; nada se pone en un span de código.

**`cli-formatos`** (`cli.py`, `report/__init__.py`, `ci.yml`)
- `--format html|md|html,md` (por defecto `html`) en `report` y en `run`. En `report`, `md` solo
  escribe `informe.md`; en `run`, `results.json` se escribe siempre.
- Formato desconocido → error de uso (código 2) con mensaje en español.
- El CI regenera `site/demo` en Markdown y comprueba que `informe.md` existe y trae el aviso.

**`capturas`** (fuera del repo, en `curso_ia_MoureDev/docs/claude-session-report/assets/`)
- `site/` servido por `python -m http.server` en local y Chrome headless con tiempo virtual
  (`--virtual-time-budget`) para parar el duelo en la fase de escritura y en el marcador final.
- Todo proceso arrancado se cierra al terminar.

**`docs-version`**: README, `docs/USO.md`, `CHANGELOG.md` (`[0.6.0] - 2026-10-01`, enlace
`v0.5.0...v0.6.0`), `AGENTS.md`, `MEMORY.md`; versión 0.6.0.

## Estilo

Como el resto del paquete: Python 3.12 solo stdlib, nombres en inglés, textos en español, ruff
(líneas de 100). Una función pequeña por bloque del informe:

```python
def md_text(value: object, limit: int = 200) -> str:
    """Texto de results.json (no fiable) listo para ir en una línea de Markdown."""
```

## Pruebas

- `pytest` con TDD: cada bloque nace de un test que falla. Los de contenido hostil (en
  `tests/test_markdown.py`) inyectan en cada campo de texto `|`, `` ` ``, `<script>`, `<img>`,
  `[x](http://…)`, `![x](…)`, `@usuario`, `#12`, `www.`/`http://`, saltos de línea, `# titulo`,
  `---`, controles y bidi, y comprueban que el resultado no contiene HTML ni enlaces sin escapar
  y que la tabla mantiene siempre el mismo número de columnas por fila.
- Prueba de ida y vuelta: cada celda hostil, des-escapada, recupera el texto original aplanado.
- CLI: `report --format md`, `html,md`, formato desconocido, `run --format`.
- Cobertura ≥ 90 %; `node --test` y la demo siguen en verde.

## Límites

- Siempre: escapar todo dato de `results.json`; tests antes del código; actualizar `MEMORY.md`.
- Preguntar antes: añadir dependencias (no se prevé ninguna), cambiar el esquema de `results.json`.
- Nunca: `html.escape` como único escapado de Markdown, copiar código o salida de modelos al
  `.md`, crear releases o etiquetas, fusionar PRs.

## Suposiciones

- El destino principal es GitHub Flavored Markdown (comentarios de PR e issues); también debe
  verse razonablemente como texto plano.
- El informe `.md` se llama `informe.md` y vive junto a `index.html` y `results.json`.
- No se publica en PyPI ni se crea release en esta fase.

## Fuera de alcance

Exportar a otros formatos (PDF, CSV), publicar el informe automáticamente en un PR, cambiar el
informe HTML.
