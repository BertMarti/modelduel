# Spec: modelduel v0.4.0 «Pro»

Estado: propuesta del agente `builder`, redactada con el encargo de Alberto como única fuente (no hubo
turno de preguntas: las suposiciones están al final y se corrigen con un comentario en el PR).

## Objetivo

Pasar de «una herramienta que genera un informe» a «una herramienta con resultados públicos»:

1. **Benchmark real con OmniRoute.** OmniRoute es un router local con API compatible con OpenAI
   (`http://localhost:20128/v1`). Un proveedor `omniroute:<modelo>` permite enfrentar cualquier modelo
   que el router exponga sin tocar variables `OPENAI_*`.
2. **Clasificación pública.** Una página estática en `site/leaderboard/`, generada por el CI a partir
   de resultados versionados en `results/*.json`, con la clasificación agregada por modelo y el
   histórico de duelos con enlace a cada informe.

Usuarios: Alberto (publica resultados reales), cualquiera que visite la web y quien clone el repo y
quiera su propia clasificación (`modelduel leaderboard <carpeta>`).

Éxito: `omniroute:modelo` funciona como `openai:modelo` con otro valor por defecto y un error claro si
el servidor no está; `https://bertmarti.github.io/modelduel/leaderboard/` muestra contenido (2-3
ligas `replay` sembradas) sin JavaScript, con el mismo diseño «duelo editorial oscuro».

## Mapa de capacidades

| Módulo | Responsabilidad | Depende de |
|---|---|---|
| `omniroute` | Proveedor alias de `openai` | (nada) |
| `leaderboard` | Agregar `results/*.json`, página, comando `leaderboard` | (nada) |
| `publicacion` | CI/deploy, enlace en la web, documentación | `leaderboard` |

Orden de construcción = un issue y un PR por módulo, encadenados en este orden.

## Alcance (mínimo con efecto «pro»)

**`omniroute`**
- `omniroute:<modelo>` reutiliza `OpenAIProvider` (clase con atributos de preset: prefijo, variable
  de URL, variable de clave, URL por defecto). Sin implementación nueva de HTTP, reintentos ni parseo.
- `OMNIROUTE_BASE_URL` (por defecto `http://localhost:20128/v1`) y `OMNIROUTE_API_KEY` (opcional).
- Sin servidor escuchando (conexión rechazada, DNS, red inalcanzable; un tiempo de espera agotado no cuenta, puede ser un modelo lento) → `ProviderError` con
  «arranca OmniRoute con `omniroute serve`» y la URL probada. Errores HTTP siguen como en `openai`.
- La clave se redacta en los errores como en `openai`; no se exige clave (OmniRoute es local).

**`leaderboard`**
- Entrada: carpeta con `results/*.json` (copias de `results.json`; un archivo por duelo o liga; la
  fecha y la versión salen del propio JSON, el id del nombre del archivo).
- Agregado por contendiente (clave: la especificación `proveedor:modelo`): nº de duelos, tareas
  resueltas y totales, tests superados y totales, coste (suma, solo si todos sus duelos tienen precio
  y la misma moneda; si no, «sin datos»; marca «ficticio» si algún precio lo es).
- Clasificación: se ordena por **tasa** de tareas resueltas, luego tasa de tests y luego coste por
  tarea (solo si es comparable), reutilizando `rank_sides`; los empates comparten posición. Se usan
  tasas, no totales, para que un modelo con más duelos no gane por volumen.
- Histórico: una fila por duelo (fecha, versión, duelo/liga, contendientes, quién ganó, enlace). Cada
  informe se regenera con `write_report` en `duelos/<id>/index.html` desde el mismo JSON.
- Página `index.html` autocontenida: CSS en línea (el de los informes + el suyo), SVG con `<title>` y
  `aria-label`, sin JavaScript, contraste AA, legible en móvil e impresión, `lang="es"`.
- Siembra: 2-3 ligas `replay` deterministas sobre `examples/tasks` (alfa, beta, gamma), con precios
  ficticios. Documentado cómo añadir resultados reales.
- Comando `modelduel leaderboard results/ --out site/leaderboard` (códigos de salida 0/1/2 como los
  demás). Errores claros (carpeta vacía, JSON ilegible, duelo `in_progress`).

**`publicacion`**
- CI y `deploy.yml` generan `site/leaderboard` con el comando; el CI comprueba la página (sin
  `<script`, contiene «Clasificación» y el histórico).
- `site/index.html` enlaza a la clasificación; `site/leaderboard/` en `.gitignore` (como `site/demo/`).
- README, `docs/USO.md`, `CHANGELOG.md` (Sin publicar), `MEMORY.md`, `AGENTS.md` al día.

## Estilo

Como el resto: Python 3.12, solo biblioteca estándar, anotaciones, `ruff` (E,F,W,I,B,UP,SIM, 100
columnas), textos de cara al usuario en español, comentarios solo para el porqué. Reutilizar
`report.html` (`e`, `fmt_*`, `svg_ratio_bar`) y `results` (`rank_sides`, `costs_comparable`).

## Criterios de éxito

1. `modelduel run ... --a omniroute:x --b openai:y` construye ambos proveedores; con el servidor
   caído, el error dice «arranca OmniRoute con `omniroute serve`» (exit 2).
2. `modelduel leaderboard results --out D` crea `D/index.html` y `D/duelos/<id>/index.html` por
   cada JSON, sin JS, con AA verificado por test y datos coherentes con `summarize`.
3. El CI genera la página, la comprueba, y el deploy la publica junto a la demo.
4. `results/` trae al menos 2 ligas `replay` y `docs/USO.md` explica cómo añadir resultados reales
   (`modelduel run ... --out DIR` y copiar `DIR/results.json` a `results/`).
5. ruff, formato, `pytest --cov` ≥ 90 % y demo en verde en Ubuntu y Windows.

## Riesgos

| Riesgo | Mitigación |
|---|---|
| El agregado por tasas engaña si los duelos usan tareas distintas | Mostrar tareas resueltas/totales y nº de duelos junto a la tasa; documentarlo |
| Resultados con marcas de tiempo distintas en cada regeneración de la siembra | La siembra es un archivo versionado, no se regenera en el CI |
| `results/*.json` crece con el código de las respuestas | Aceptado (KB por liga); revisar si pasa de unos MB |
| JSON manipulado inyecta HTML | `e()` en todo texto del JSON y test específico |
| OmniRoute no sigue exactamente Chat Completions | Parseo tolerante ya existente; prueba manual de Alberto (pendiente) |
| Excepción de conexión distinta según SO | Mapear los errores de red de `post_json`; test con `ConnectionRefusedError` y `URLError` |

## Suposiciones (corrígelas en el PR)

1. «Modelo» en la clasificación = la especificación completa (`omniroute:gpt-x` y `openai:gpt-x` son
   filas distintas).
2. Un duelo `in_progress` en `results/` es un error, no se ignora en silencio.
3. Los informes se regeneran desde el JSON (no se versionan los HTML).
4. El coste agregado es la suma de los duelos; no se convierte entre monedas.
